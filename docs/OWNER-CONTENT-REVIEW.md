# Owner Content and Consent Review

**Purpose:** provide the final owner inputs needed before staging content is treated as release-ready. This checklist is content and approval work; it does not grant production CMS access or change the public site by itself.

## How to use this checklist

Review the staging site and mark each item only after the wording, facts, permissions, and presentation are approved. If an item is not ready, leave it unchecked and record the decision or missing input below it.

## Public site copy

- [✓ ] Homepage hero, supporting copy, and primary CTAs approved.
- [ ✓] Services overview heading, capability names, descriptions, and CTA labels approved.
- [✓ ] All five service detail pages approved, including audience, outcome, supporting copy, and CTA wording.
- [ ✓] About page copy approved, including people/team language and any “coming later” statements.
- [ ✓] Contact page heading, supporting copy, field labels, select options, validation messages, and success message approved.
- [ ✓] Footer tagline, navigation labels, copyright line, and contact CTA approved.
- [✓ ] SEO titles, descriptions, Open Graph title/description, and social preview image approved for each public route.

## Case-study publication approval

For every project intended to appear in `/work`, confirm the following.

- [ ✓] Project name and slug approved.
- [ ✓] Project type and category approved.
- [ ✓] Client visibility decision recorded: named, anonymized, or hidden.
- [ ✓] Summary, challenge, approach, deliverables, and outcomes approved.
- [ ✓] External project URL approved, or explicitly marked as unavailable.
- [ ✓] Featured image approved for publication, with final alt text.
- [ ✓] Supporting images approved for publication, with final alt text for each image.
- [ ✓] Permission confirmed for every logo, screenshot, testimonial, metric, and client reference.
- [ ✓] Featured order and related capabilities approved.
- [ ✓] Placeholder treatment approved for any missing evidence or imagery.

## Contact and privacy approval

- [ ✓] Inquiry recipient/owner is confirmed.
- [ ✓] Form fields are limited to the information OCSCO needs to qualify an inquiry.
- [ ✓] Privacy/consent wording is approved and linked to the intended privacy policy.
- [ ✓] Confirmation message and expected response time are approved.
- [ ✓] Spam-protection behavior is acceptable and does not create misleading feedback.
- [ ✓] Data retention and deletion expectation for inquiries is confirmed.

- [ ✓] Desktop review completed for every public route.
